# 不自动创建未解析链接的目标节点

---
status: accepted
---

当 Wiki 中的语义链接指向当前 workspace 不存在的页面时，compile 和 Obsidian CLI 健康检查只将其报告为未解析链接，不根据链接文本自动创建占位节点。链接可能是笔误、尚未确认的概念或错误的跨 workspace 引用；只有用户明确确认后，系统才创建候选节点或正式节点并补齐关系。

## Consequences

- 图谱不会因为一个链接拼写就产生虚假的开发事实。
- 未解析链接需要在 overview 和健康检查结果中保持可见，直到被修复或确认。
- 节点创建流程必须区分“修复引用”和“确认新事实”。
