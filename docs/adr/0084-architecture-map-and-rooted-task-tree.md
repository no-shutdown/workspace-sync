# 将架构地图与开发任务树分开呈现

- 状态：accepted
- 日期：2026-07-27

## 背景

同一张图同时放入系统、能力、缺口、开发任务、依赖和联调关系后，能够表达事实，却不适合快速阅读。架构设计需要看系统边界、能力和缺口；开发执行需要看开发总任务下的任务分解、状态和前置条件。两种阅读目标不同，不能继续用一张默认大图承载。

## 决策

保留正式节点类型只有 `系统`、`能力`、`缺口`、`任务` 四类，并为每个 workspace 建立唯一的开发总任务根节点：

```text
图谱/节点/任务/任务-开发总任务.md
```

根节点仍使用 `type: 任务`，仅通过 `task_role: 根任务` 标记角色，不引入 Epic、项目或其他新类型。每个非根任务必须恰好通过一条 `分解为` 关系从根任务可达；`分解为` 无环且只允许任务到任务。`依赖` 是独立的跨分支前置关系，不改变任务树的父子层级，也不自动改变任务状态。

## 视图职责

- `架构地图.md`：只画系统的 `包含` 层级、系统提供的能力、系统存在的缺口和缺口的目标能力；不画任务树或任务依赖。
- `开发任务.md`：以 `任务-开发总任务` 为根，用嵌套列表展开任务树，并显示状态、依赖、涉及系统、解决缺口、项目支撑记录和下一步。
- `开发路线.md`：作为架构与任务的桥接索引，按系统/缺口列出解决任务和任务树路径；不维护第二套层级，也不生成大 Mermaid 图。
- `系统联调.md`：单独呈现系统之间的 `需要联调` 关系及关联任务。
- `总览.md`：同时显示架构面包屑和任务面包屑，并链接到架构地图与开发任务。

所有视图都是正式节点正文关系的可重建投影，不承载独立事实。

## 健康检查与迁移

compile 在生成任务树前检查唯一根、唯一父级、根可达性、无环、关系端点和未归位任务。缺失父级、多父级、循环或不可达任务只生成 warning/候选归属，不自动补链或把依赖改成父子关系。迁移保留节点 ID、aliases、正文、状态和历史；旧任务清单只迁移为生成视图 `开发任务.md`，不把清单顺序推断为层级。

## 后果

- 人可以从架构地图快速判断系统设计和能力缺口，从开发任务快速判断当前开发处于总任务的哪一层。
- 任务树的父子结构与依赖结构分离，既保留执行顺序，又避免依赖线制造错误层级。
- 需要接受多个入口页面和更严格的任务树健康 warning；坏关系不会被编译器静默修复。
