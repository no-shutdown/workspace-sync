# 将开发图谱正式类型精简为四类

- 状态：accepted
- 日期：2026-07-27
- supersedes：ADR-0082 在正式类型和视图命名上的相关约定

## 背景

当前开发图谱把项目、系统、能力、能力缺口、任务和决策都作为正式节点类型。它能够表达丰富语义，但把架构边界、目标能力、当前问题、执行动作和支撑资料放在同一层，导致个人 Obsidian 图谱难以回答两个核心问题：当前开发位于架构哪一层，以及下一步有哪些任务。

## 决策

正式图谱类型固定为四类：

- 系统：运行或架构边界；
- 能力：系统应提供或已提供的可观察行为/结果；
- 缺口：目标能力与当前实际能力之间已确认的缺失；
- 任务：可执行、可跟踪的开发工作。

项目降级为 `图谱/说明/项目/` 下的支撑记录，保存代码仓库身份、remote、分支、HEAD 和 dirty 状态。决策降级为 `图谱/说明/决策/` 下的支撑记录，保存技术选择及理由。联调不创建节点，使用系统之间的 `需要联调` 关系；复杂联调细节才保存为 `图谱/说明/联调/` 普通说明。

正式节点文件名和 frontmatter `type` 都使用中文 `类型-名称` 规则。稳定 ID 不因类型、目录或名称迁移而改变。

## 关系与视图

主关系固定为：

```text
系统 ──包含──> 系统
系统 ──提供──> 能力
系统 ──存在缺口──> 缺口
缺口 ──目标能力──> 能力
任务 ──解决──> 缺口
任务 ──涉及系统──> 系统
任务 ──分解为/依赖──> 任务
系统 ──需要联调──> 系统
```

活动任务的架构位置优先沿 `任务 → 解决 → 缺口 → 存在缺口 → 系统` 计算；没有缺口链路时使用 `任务 → 涉及系统`。无法定位只生成 warning，不按名称或项目记录猜测。

compile 生成：

- `架构地图.md`：系统层级、能力和缺口摘要；
- `开发路线.md`：系统 → 缺口 → 任务；
- `任务清单.md`：任务状态、依赖、涉及系统和下一步；
- `系统联调.md`：系统协作关系及相关任务。

总览页只展示当前定位、关键缺口、阻塞任务和视图入口，不生成全量大图。项目、决策、候选和健康问题不进入四张主图。

## 迁移与兼容

旧的项目/决策节点移动为支撑记录；旧的 `能力缺口` 类型迁移为 `缺口`；旧的联调点保留为待处理说明；未知类型进入 `图谱/候选/` 的待确认列表。迁移保留稳定 ID、aliases、来源、正文和历史，不自动合并同名页面，不自动把缺口、项目或决策转换为其他正式节点。

历史关系 `取代`、`派生自` 和 `参考决策`继续保留用于追溯，但不参与主视图和架构路径计算。

## 后果

正面影响：

- 主图只保留架构、能力、问题和行动四个必要层次；
- 任务可以稳定映射回系统架构位置；
- 项目现场和技术决策仍可追溯，但不会干扰个人日常导航；
- 类型、目录和视图名称更短，降低 compile 的判断分歧。

代价：

- 项目和决策不再拥有正式图谱节点统计，需要通过支撑目录查看；
- 旧链接和旧目录需要执行一次明确确认的迁移；
- 需要通过 `涉及系统` 为没有缺口链路的任务补齐架构定位。
