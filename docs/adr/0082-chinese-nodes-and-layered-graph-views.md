# 使用中文节点目录并生成分层图谱视图

---
status: accepted
---

## 背景

Obsidian 的全局关系图会把系统、能力、能力缺口、任务、项目和决策全部作为同一层的页面展示。节点默认使用英文目录和稳定 ID 命名，导致个人阅读时难以识别对象含义；如果继续把所有关系加入同一张图，增加父子边也不能稳定表达架构层级。

## 决策

1. workspace 内用户可见的目录、节点类型文件夹和节点文件名统一使用中文。
2. 正式节点文件名固定为 `类型-名字.md`，例如 `系统-订单平台.md`。稳定 `id` 仍保存在 frontmatter 中，改名不改变身份；同类型同名页面不自动合并。
3. 正式节点类型收敛为：项目、系统、能力、能力缺口、任务、决策。功能归入能力。
4. 联调点不再作为正式节点类型；系统之间用“需要联调”关系表达。接口、数据、时序和验收细节写在相关系统或任务页面中。
5. 新增“包含”关系表达系统到子系统的架构层级；“分解为”只表达任务层级，“依赖”只表达任务依赖；联调任务通过“关联系统”标明参与系统。
6. compile 生成四个聚焦视图：系统架构、能力缺口、开发任务和系统联调。视图可以使用 Mermaid 和链接列表，但节点正文中的语义关系仍是唯一事实来源。
7. 总览只呈现关键摘要和视图入口，索引呈现完整目录；决策、项目和健康问题默认不进入系统架构主图。
8. compile 按中文类型和规范化标题执行重复检查；重复或疑似同义节点进入候选队列，必须由用户确认后才能合并。

## 结果

- Obsidian 文件夹和节点名称直接面向个人阅读，不需要先翻译英文 slug。
- 系统架构链路、能力缺口链路和任务依赖链路被分离，用户可以按问题进入对应视图。
- 项目和决策仍然保留可追溯性，但不会让主架构图产生额外噪声。
- 旧版 `raw/`、`wiki/`、`nodes/`、英文类型和值以及 `联调点` 节点需要在迁移时转换；转换过程保留旧 ID 和历史来源。

## 取舍

Obsidian 全局图仍然保留作为探索工具，但不再承担“架构总览”的职责。架构总览以生成的分层页面为准；如果未来需要自由拖拽布局，可以在不改变 Markdown 事实源的前提下增加 Canvas 投影。
