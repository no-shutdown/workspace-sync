# 以开发图谱作为工作空间的核心模型

---
status: accepted
---

工作空间以开发图谱作为核心事实模型，而不是以严格任务树或任务清单作为唯一结构。图谱用有类型的节点和有语义的关系映射开发现实，节点可以包括项目、系统、功能、能力缺口、联调点、决策和任务；任务是其中代表可执行工作的节点，可以从图谱中识别出的缺口、联调需要或其他开发事实派生出来。主任务、子任务和任务列表只是图谱的派生视图或关系，不限制整个图谱必须是树形。

## Supersedes

- ADR-0007：使用严格树形组织工作空间任务

## Consequences

- 图谱节点和关系需要明确类型与语义，不能只保存无意义的双向链接。
- 一个任务可以同时关联多个项目、系统或能力缺口。
- 系统缺少什么功能、哪些系统需要联调、哪些任务被什么阻塞，应能从同一图谱中观察出来。
- 任务清单、项目视图、依赖视图和图谱可视化都应视为不同的读取视图，而不是互相独立的事实来源。
