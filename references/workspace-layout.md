# workspace 与图谱布局

## 根目录

~~~text
knowledge-base/
├── SCHEMA.md
└── <工作区名称>/
    ├── 工作区.md
    ├── 原始资料/
    └── 图谱/
        ├── 总览.md
        ├── 索引.md
        ├── 日志.md
        ├── 节点/
        │   ├── 系统/
        │   ├── 能力/
        │   ├── 缺口/
        │   └── 任务/
        ├── 视图/
        │   ├── 架构地图.md
        │   ├── 开发路线.md
        │   ├── 任务清单.md
        │   └── 系统联调.md
        ├── 说明/
        │   ├── 项目/
        │   ├── 决策/
        │   └── 联调/
        └── 候选/
~~~

workspace 文件夹是用户可读的中文名称，可以受控改名；新建 workspace 时默认要求输入中文名称。workspace 身份以 `工作区.md` 中的稳定 ID 为准。

# 数据导入迭代

## 归档

尚未归档。
~~~

允许的生命周期：`active`、`paused`、`archived`。完成或放弃一个迭代时归档，不默认物理删除。

## 原始资料

`原始资料/` 只要求文件名以 `.md` 结尾。内容可以是会议笔记、规划稿、问题记录、设计讨论或工具输出，不要求模板。compile 不把原始资料转移到别处，也不覆盖它。

推荐文件名包含日期和中文主题，例如：

~~~text
原始资料/2026-07-27-系统联调规划.md
原始资料/2026-07-28-后续讨论.md
~~~

文件名不是事实身份；节点稳定 ID 和来源引用才是身份依据。

## 正式节点页面

正式节点只有四类，路径和文件名使用中文类型前缀：

~~~text
图谱/节点/系统/系统-业务平台.md
图谱/节点/能力/能力-数据导入.md
图谱/节点/缺口/缺口-数据导入缺少幂等校验.md
图谱/节点/任务/任务-实现数据导入幂等校验.md
~~~

最小 frontmatter：

~~~yaml
---
id: task-xxxx
type: 任务
title: 实现数据导入幂等校验
aliases:
  - task-xxxx
created_at: 2026-07-27T10:00:00+08:00
updated_at: 2026-07-27T10:00:00+08:00
source_refs:
  - ../../../原始资料/2026-07-27-系统联调规划.md
---
~~~

任务节点额外包含 `status`。YAML 不存正式语义关系；关系放在 Markdown 正文中：

~~~md
## 关系

- 涉及系统：[[系统-业务平台]]
- 解决：[[缺口-数据导入缺少幂等校验]]
- 依赖：[[任务-完成认证改造]]
~~~

文件名是可读显示名，不是身份来源。编译器通过 `id` 建立 ID 到页面路径的映射；改名时保留 ID 和 alias，并更新当前 workspace 内的中文 Wiki 链接。同类型同名节点不能自动合并，必要时在文件名后追加稳定 ID 短后缀并生成重复候选。

## 支撑记录

项目、决策和详细联调说明不属于正式节点：

~~~text
图谱/说明/项目/数据服务.md
图谱/说明/决策/采用幂等键.md
图谱/说明/联调/数据服务与业务平台.md
~~~

支撑记录可以被普通 Markdown 链接引用，但不参与正式节点统计、架构路径计算和主 Mermaid 图。项目记录中的本机路径只进入 local state。

## 候选页面

候选位于 `图谱/候选/`，例如：

~~~md
---
candidate_id: candidate-task-001
kind: task
status: pending
title: 增加数据导入联调测试
source_refs:
  - ../../原始资料/2026-07-27-系统联调规划.md
---

## 推导理由

由 [[缺口-数据导入缺少幂等校验]] 和系统之间的“需要联调”关系推导。

## 决策

待用户确认。
~~~

确认后创建新的正式任务页；候选页不改成正式任务页，不复用候选 ID。

## 生成页面

- `图谱/总览.md`：面向人和新 AI 的当前接手视图，可重建；显示当前架构位置。
- `图谱/索引.md`：四类正式节点和支撑记录的完整目录，可重建。
- `图谱/视图/架构地图.md`：系统层级、能力和缺口摘要，可重建。
- `图谱/视图/开发路线.md`：系统 → 缺口 → 任务，可重建。
- `图谱/视图/任务清单.md`：任务状态、依赖、涉及系统和下一步，可重建。
- `图谱/视图/系统联调.md`：系统联调关系和关联任务，可重建。
- `图谱/日志.md`：操作、输入、输出、冲突、项目采集和健康问题状态变化的追加审计日志。

生成页面不承载独立事实；人工修改进入原始资料或具体节点页面。

## 隔离规则

正式语义 Wiki 链接必须指向同一 workspace 内的正式节点。支撑记录可以使用普通 Markdown 链接；跨 workspace 引用不参与 compile、图谱关系或健康检查，如用户需要可以明确写成普通外部引用。
