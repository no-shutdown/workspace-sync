# 分层图谱视图

分层视图是正式节点和正文关系的阅读投影，不是第二份数据库。所有视图由 compile 重建，人工事实必须写入原始资料或正式节点页面。

## 视图边界

| 视图 | 默认显示 | 默认隐藏 |
| --- | --- | --- |
| `架构地图.md` | 系统、系统包含关系、能力、各系统缺口数量摘要 | 任务树、任务依赖、项目、决策、健康问题 |
| `开发任务.md` | 唯一根任务、任务树、状态、依赖、涉及系统、解决缺口、实现项目支撑记录、下一步 | 系统架构 Mermaid 细节、普通能力、项目/决策节点和详细记录 |
| `开发路线.md` | 系统/缺口、解决任务、任务状态和任务树路径 | 第二套任务层级、系统内部无关能力、项目详情、决策 |
| `系统联调.md` | 系统之间的需要联调关系、涉及系统的任务 | 普通能力、无关任务、项目详情、决策 |

`总览.md` 至少展示当前目标、当前架构位置、分层视图入口、关键缺口、任务状态、阻塞任务、待确认项、候选、冲突、健康 warning 和下一步；它不把所有节点复制到一张大图中。`索引.md` 负责完整目录。

## 正式关系

- `包含`：系统 → 系统，表示架构层级。
- `提供`：系统 → 能力。
- `存在缺口`：系统 → 缺口。
- `目标能力`：缺口 → 能力。
- `解决`：任务 → 缺口。
- `涉及系统`：任务 → 系统，用于任务的架构定位和跨系统范围。
- `分解为`：任务 → 任务，只用于开发任务树的父子层级。
- `依赖`：任务 → 任务，只用于跨分支前置条件；不参与任务树缩进。
- `需要联调`：系统 → 系统；展示时按无向协作边去重。

`取代`、`派生自`、`参考决策`只用于历史或支撑追溯，不参与主视图。

## 当前架构位置

活动任务的面包屑优先从以下链路计算：

```text
任务 → 解决 → 缺口 → 存在缺口 → 系统 → 包含 → 顶层系统
```

任务没有缺口链路时，使用：

```text
任务 → 涉及系统 → 顶层系统
```

两条路径都不存在时，视图列为未定位任务 warning；不根据名称或项目名称猜测架构归属。

## AI 局部上下文

人通过 `架构地图.md`、`开发任务.md`、`开发路线.md` 和 `系统联调.md` 选择阅读入口；AI 不把这些视图拼成第二张事实图，而是以已确认的焦点任务为种子，回到节点正文装配有限的局部上下文闭包：

- 任务侧沿 `分解为` 反向读取到 `任务-开发总任务` 的完整父级链，读取直接子任务、直接依赖和未完成的直接依赖者；`依赖` 不改变任务树层级，也不默认递归二阶依赖。
- 架构侧沿 `解决`、`涉及系统`、`包含`、`提供`、`存在缺口` 和 `需要联调` 读取缺口、能力、系统祖先/直接子系统及联调入口。
- 支撑侧只读取与焦点任务或架构邻域直接关联的项目、决策和联调说明；`source_refs` 指向的原始资料按需展开。

上下文的任务面包屑和架构面包屑必须分别来自正式节点关系。总览、任务树、架构图、开发路线中的摘要、缩进、Mermaid 标签和桥接表只提供入口；与节点正文不一致时以节点正文为准并报告页面过期。没有明确焦点时不按名称、项目、页面邻近或最近修改时间猜测；缺父级、未解析链接、缺少架构定位或邻域过大时保留 warning，延迟二阶内容，不自动补关系或加载全库。

## 架构地图与 Mermaid 约定

`架构地图.md` 是唯一默认使用 Mermaid 展示架构关系的视图。Mermaid 节点内部 ID 使用稳定的 ASCII `id`，显示标签使用中文文件名；不要把中文文件名直接当 Mermaid ID。节点图后面同时生成中文 Wiki 链接列表，确保页面可导航。架构图只使用系统的 `包含`、系统到能力的 `提供`、系统到缺口的 `存在缺口` 和缺口到能力的 `目标能力`；任务及其 `分解为`/`依赖` 关系不进入此图。

架构地图示意：

~~~mermaid
flowchart TB
    S_platform["系统-业务平台"]
    S_data["系统-数据平台"]
    C_import["能力-数据导入"]

    S_platform -->|包含| S_data
    S_data -->|提供| C_import
    S_data -.->|缺口数量: 1| G_summary["未解决缺口: 1"]
~~~

## 开发任务树

`开发任务.md` 以 `[[任务-开发总任务]]` 为唯一根节点，用 Markdown 缩进列表表达 `分解为` 关系；每个任务旁边显示状态、架构定位、解决缺口和依赖。`依赖` 使用单独字段或链接列展示，不能改变任务缩进，也不能产生第二棵树。

任务树示意：

~~~md
- [[任务-开发总任务]] · 进行中
  - [[任务-建设数据导入]] · 进行中 · 涉及 [[系统-数据平台]]
    - [[任务-实现数据导入幂等校验]] · 待开始 · 解决 [[缺口-数据导入缺少幂等校验]]
      - 依赖：[[任务-完成认证改造]]
  - [[任务-完成认证改造]] · 已完成
~~~

任务树生成前必须验证根任务恰好一个、每个非根任务恰好一个父级、`分解为` 无环且所有任务从根可达。异常任务仍可在“未归位任务”章节列出，但不能被编译器静默补入任意分支。

## 开发路线桥接

`开发路线.md` 是快速回答“架构哪里还缺、由哪些任务解决”的索引，不是第二个任务视图。它可以使用表格或短列表，不生成大 Mermaid 图，不复制任务树，只引用任务树路径：

| 架构对象 | 关系 | 解决任务 | 任务树路径 |
| --- | --- | --- | --- |
| [[系统-数据平台]] | 存在缺口 | [[任务-实现数据导入幂等校验]] | [[任务-开发总任务]] → 建设数据导入 → 实现数据导入幂等校验 |
| [[缺口-数据导入缺少幂等校验]] | 解决 | [[任务-实现数据导入幂等校验]] | [[任务-开发总任务]] → 建设数据导入 → 实现数据导入幂等校验 |

系统联调关系继续单独放在 `系统联调.md`，必要时在任务树中通过“需要联调”或关联任务链接回系统。

## 规模控制

- 总览图只显示顶层系统、未解决缺口数量和阻塞任务数量。
- 单个视图超过 30 个节点时，优先按顶层系统拆成章节，并保留每个系统的入口链接。
- 已完成任务默认折叠到“已完成”列表，不占用活动任务树的空间。
- 项目和决策不作为节点进入四张主图；开发任务可以用纯文本列出实现项目支撑记录。候选和健康问题只在总览/索引的对应列表中出现，不进入主视图。
- `包含` 出现循环、一个系统存在多个主父级或节点无法归入架构树时，只报告 warning，不自动添加父节点。
