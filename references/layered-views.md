# 分层图谱视图

分层视图是正式节点和正文关系的阅读投影，不是第二份数据库。所有视图由 compile 重建，人工事实必须写入原始资料或正式节点页面。

## 视图边界

| 视图 | 默认显示 | 默认隐藏 |
| --- | --- | --- |
| `架构地图.md` | 系统、系统包含关系、能力、各系统缺口数量摘要 | 缺口详情、任务、项目、决策、健康问题 |
| `开发路线.md` | 系统、缺口、解决任务、任务状态 | 系统内部无关能力、项目详情、决策、任务依赖细节 |
| `任务清单.md` | 任务、状态、依赖、涉及系统、实现项目支撑记录、下一步 | 系统架构 Mermaid 细节、普通能力、项目/决策节点和详细记录、健康问题 |
| `系统联调.md` | 系统之间的需要联调关系、涉及系统的任务 | 普通能力、无关任务、项目详情、决策 |

`总览.md` 至少展示当前目标、当前架构位置、分层视图入口、关键缺口、任务状态、阻塞任务、待确认项、候选、冲突、健康 warning 和下一步；它不把所有节点复制到一张大图中。`索引.md` 负责完整目录。

## 正式关系

- `包含`：系统 → 系统，表示架构层级。
- `提供`：系统 → 能力。
- `存在缺口`：系统 → 缺口。
- `目标能力`：缺口 → 能力。
- `解决`：任务 → 缺口。
- `涉及系统`：任务 → 系统，用于任务的架构定位和跨系统范围。
- `分解为`：任务 → 任务。
- `依赖`：任务 → 任务。
- `需要联调`：系统 → 系统；展示时按无向协作边去重。

`取代`、`派生自`、`参考决策`只用于历史或支撑追溯，不参与主视图。

## 当前架构位置

活动任务的面包屑优先从以下链路计算：

```text
任务 → 解决 → 缺口 → 存在缺口 → 系统 → 包含 → 顶层系统
```

任务没有缺口链路时，使用：

```text
任务 → 涉及系统 → 顶层系统
```

两条路径都不存在时，视图列为未定位任务 warning；不根据名称或项目名称猜测架构归属。

## Mermaid 约定

Mermaid 节点内部 ID 使用稳定的 ASCII `id`，显示标签使用中文文件名；不要把中文文件名直接当 Mermaid ID。节点图后面同时生成中文 Wiki 链接列表，确保页面可导航。

架构地图示意：

~~~mermaid
flowchart TB
    S_platform["系统-业务平台"]
    S_data["系统-数据平台"]
    C_import["能力-数据导入"]

    S_platform -->|包含| S_data
    S_data -->|提供| C_import
    S_data -.->|缺口数量: 1| G_summary["未解决缺口: 1"]
~~~

开发路线示意：

~~~mermaid
flowchart TB
    S_data["系统-数据平台"]
    G_idempotent["缺口-数据导入缺少幂等校验"]
    T_idempotent["任务-实现数据导入幂等校验\n进行中"]

    S_data -->|存在缺口| G_idempotent
    T_idempotent -->|解决| G_idempotent
~~~

任务清单定位示意：

~~~mermaid
flowchart TB
    T_idempotent["任务-实现数据导入幂等校验"]
    S_data["系统-数据平台"]
    G_idempotent["缺口-数据导入缺少幂等校验"]

    T_idempotent -->|涉及系统| S_data
    T_idempotent -->|解决| G_idempotent
~~~

## 规模控制

- 总览图只显示顶层系统、未解决缺口数量和阻塞任务数量。
- 单个视图超过 30 个节点时，优先按顶层系统拆成章节，并保留每个系统的入口链接。
- 已完成任务默认折叠到“已完成”列表，不占用主 Mermaid 图的空间。
- 项目和决策不作为节点进入四张主图；任务清单可以用纯文本列出实现项目支撑记录。候选和健康问题只在总览/索引的对应列表中出现，不进入四张主图。
- `包含` 出现循环、一个系统存在多个主父级或节点无法归入架构树时，只报告 warning，不自动添加父节点。
