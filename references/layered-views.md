# 分层图谱视图

分层视图是正式节点和正文关系的阅读投影，不是第二份数据库。所有视图由 compile 重建，人工事实必须写入原始资料或正式节点页面。

## 视图边界

| 视图 | 默认显示 | 默认隐藏 |
| --- | --- | --- |
| `系统架构.md` | 系统、系统包含关系、能力、项目实现映射 | 能力缺口、任务、决策、健康问题 |
| `能力缺口.md` | 系统、能力缺口、解决任务、任务状态 | 系统内部无关的项目、决策、任务依赖 |
| `开发任务.md` | 任务分解、任务状态、任务依赖、关联项目 | 系统架构细节、能力节点、健康问题 |
| `系统联调.md` | 系统之间的需要联调关系、关联系统的任务 | 普通能力、无关任务、决策 |

`总览.md` 只展示当前目标、视图入口、关键缺口、阻塞任务和数量摘要，不把所有节点复制到一张大图中。`索引.md` 负责完整目录。

## 正式关系

- `包含`：系统 → 系统，表示架构层级。
- `提供`：系统 → 能力。
- `缺少`：系统 → 能力缺口。
- `目标能力`：能力缺口 → 能力。
- `解决`：任务 → 能力缺口。
- `分解为`：任务 → 任务。
- `依赖`：任务 → 任务。
- `需要联调`：系统 → 系统；展示时按无向协作边去重。
- `关联系统`：任务 → 系统，用于在联调视图中定位任务。
- `关联项目`：任务/系统 → 项目，用于实现映射和任务归属。

## Mermaid 约定

Mermaid 节点内部 ID 使用稳定的 ASCII `id`，显示标签使用中文文件名；不要把中文文件名直接当 Mermaid ID。节点图后面同时生成中文 Wiki 链接列表，确保页面可导航。

系统架构示意：

~~~mermaid
flowchart TB
    S_platform["系统-订单平台"]
    S_order["系统-订单服务"]
    C_import["能力-订单导入"]
    P_order["项目-订单服务"]

    S_platform -->|包含| S_order
    S_order -->|提供| C_import
    S_order -.->|关联项目| P_order
~~~

能力缺口示意：

~~~mermaid
flowchart TB
    S_order["系统-订单服务"]
    G_idempotent["能力缺口-订单导入缺少幂等校验"]
    T_idempotent["任务-实现订单导入幂等校验"]

    S_order -->|缺少| G_idempotent
    T_idempotent -->|解决| G_idempotent
~~~

开发任务示意：

~~~mermaid
flowchart TB
    T_import["任务-完成订单导入"]
    T_auth["任务-先完成认证改造"]
    T_idempotent["任务-实现订单导入幂等校验"]

    T_import -->|分解为| T_idempotent
    T_idempotent -.->|依赖| T_auth
~~~

## 规模控制

- 总览图只显示顶层系统、未完成能力缺口数量和阻塞任务数量。
- 单个视图超过 30 个节点时，优先按顶层系统拆成章节，并保留每个系统的入口链接。
- 已完成任务默认折叠到“已完成”列表，不占用主 Mermaid 图的空间。
- 决策、候选和健康问题只在总览的对应列表中出现，不进入四张主图。
- `包含` 出现循环、一个系统存在多个主父级或节点无法归入架构树时，只报告 warning，不自动添加父节点。
