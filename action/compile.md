# compile

## 命令

```text
/workspace-sync compile
```

这是 AI 对话中的 workspace-sync 指令。它使用已经选择的当前 workspace，不另加 workspace 参数，也不读取其他迭代。

## 目标

把当前 workspace 的自由格式原始资料，或当前会话中已经明确确认的规划结论，增量整理为 Karpathy LLM Wiki 风格的开发图谱：保留原始资料，维护四类正式节点、支撑记录、候选、关系、分层视图、冲突和操作日志。

## 输入边界

- 默认扫描当前 workspace 的 `原始资料/*.md`。
- 原始资料不要求固定格式、章节、YAML 或 frontmatter。
- 新规划内容必须追加为新的原始资料，不覆盖以前的原始资料。
- 完整对话不是 compile 的必需输入，也不默认保存完整对话。
- 没有原始资料时，只有当前会话中已经明确确认的开发任务/规划结论才能生成新的原始资料；未确认想法只能生成待确认项。

## 步骤

### 1. 确认上下文

读取：

- 根 `SCHEMA.md`；
- 当前 workspace 的 `工作区.md`；
- 当前 workspace 的 `图谱/总览.md`、`图谱/索引.md`、`图谱/日志.md` 和 `图谱/视图/`；
- 受影响的原始资料、正式节点、支撑记录和候选页面。

对 Vault 内容的读取使用 Obsidian CLI。若当前 workspace 不存在，要求用户输入名称并先初始化，不猜测或借用其他 workspace。

### 2. 产生原始资料（仅在需要时）

如果输入来自当前 AI 会话而不是已有原始资料：

1. 从会话中提取用户明确确认的目标、任务、约束、关系、决策和验收边界；
2. 以自由格式 Markdown 创建一个新的 `原始资料/<timestamp>-planning.md`；
3. 记录来源是当前会话和确认范围，不保存完整对话；
4. 没有明确确认内容时，不生成正式原始资料事实，向用户报告待确认项。

原始资料通过 Obsidian CLI 创建，创建后不可被 compile 覆盖。

### 3. 增量编译图谱

对新增或变化的原始资料：

- 只识别四类正式节点：系统、能力、缺口、任务；
- 项目资料写入 `图谱/说明/项目/` 支撑记录，不创建正式项目节点；
- 技术决策写入 `图谱/说明/决策/` 支撑记录，不创建正式决策节点；
- 联调事实编译为系统之间的 `需要联调` 关系；需要详细接口、数据、时序或验证规则时才创建 `图谱/说明/联调/` 普通说明页；
- 新节点的 frontmatter `type` 使用中文值：`系统`、`能力`、`缺口`、`任务`；旧节点的英文类型和旧中文类型只作为迁移兼容输入；
- 遇到未知或旧的 `type`（例如 `项目`、`决策`、`联调点`、`integration`、`epic`、`architecture`、`development-task`）时，不作为正式节点编译；保留原页面并放入迁移候选或对应支撑记录，等待明确映射；
- 节点文件名使用 `类型-中文名称.md`，默认生成中文文件夹 `图谱/节点/<类型>/`；改名保留稳定 `id`，同名节点不自动合并；
- 每个 workspace 只允许一个任务根页 `图谱/节点/任务/任务-开发总任务.md`；它仍是 `type: 任务`，用 `task_role: 根任务` 标记，不新增节点类型；
- 用稳定节点 ID 匹配已有节点；名称相同不能自动合并；
- 在节点正文中维护中文语义 Wiki 链接，例如 `[[缺口-数据导入缺少幂等校验]]`；稳定 ID 可作为 alias 保留；
- YAML 只保存正式节点身份、类型、任务角色（仅根任务需要）、状态、时间和来源；项目/决策引用属于支撑信息，不复制正式关系表；
- 关系端点必须符合 `SCHEMA.md`：系统层级使用 `包含`，系统能力使用 `提供`，系统问题使用 `存在缺口`，缺口目标使用 `目标能力`，任务问题使用 `解决`，任务定位使用 `涉及系统`，任务层级使用 `分解为`，任务前置使用 `依赖`，系统协作使用 `需要联调`；
- `取代`、`派生自`、`参考决策`只用于历史或支撑追溯，不参与架构路径计算和主视图；
- 编译前按“中文类型 + 规范化标题”检查重复；完全重复或高度疑似同义时生成 `kind: duplicate` 的待确认候选，不能自动删除、合并或用新节点覆盖旧节点；
- 同一目标/验收边界的变化保留原任务 ID 并追加修订历史；整体改写时保留旧任务，创建新任务并建立 `取代` 关系；
- 任务状态只有用户明确确认或明确事实支持时才变更；不能由 AI 猜测、子任务完成或代码提交静默更新。

### 4. 计算当前架构定位

对活动正式任务生成当前开发位置：

1. 优先沿 `任务 → 解决 → 缺口 → 存在缺口 → 系统` 计算系统层级路径；
2. 没有缺口链路时，使用 `任务 → 涉及系统` 定位；
3. 任务涉及多个系统时保留多个定位，不强行选择一个主系统；
4. 两条路径都不存在时生成 warning“任务缺少架构定位”，不按任务名称、项目名称或最近编辑内容猜测。

不能因为系统没有 `提供` 关系，就自动推断能力缺失；只有明确的 `存在缺口` 事实才能生成缺口。

### 5. 验证任务树

在生成任务视图前，从正式任务节点的 `分解为` 关系构造任务树：

1. `task_role: 根任务` 的节点必须恰好一个，并且固定为 `任务-开发总任务`；
2. 根任务不能有父任务；每个其他任务必须恰好有一个 `分解为` 父任务；
3. `分解为` 的起点和终点都必须是任务，关系图无环；
4. 每个正式任务都必须从根任务可达；
5. `依赖` 单独保留为跨分支前置关系，不参与父子树、根可达性和任务缩进。

发现缺失根、多根、缺失父级、多父级、循环或不可达任务时，只生成稳定指纹 warning 和待确认候选归属；不自动补父级、不把 `依赖` 改成 `分解为`，不因此改写用户确认的任务状态。任务树仍可以生成，但异常任务标记为“未归位”，避免一条坏边阻断整份接手视图。

### 6. 处理不确定、冲突和候选

- “可能、考虑、待确认、以后再看”等内容进入当前 workspace 的待确认项，不进入确定事实；
- 互相冲突的原始资料都保留，相关节点标记冲突；无冲突内容照常编译；
- 从缺口或系统联调需要推导出的工作只生成 `图谱/候选/` 候选页，不直接创建正式任务；
- 只有原始资料明确给出任务内容时才创建任务；仅有“有 N 个任务”的数量描述时不创建占位页面；
- 用户确认候选后，创建新稳定 ID 的正式任务并保留候选页的转化历史；
- 用户拒绝候选后保留拒绝理由，隐藏在待处理列表中，除非新证据出现，不重复建议；
- 删除任务使用软删除，保留 ID、历史和删除记录。

### 7. 生成分层视图

通过 Obsidian CLI 重建当前 workspace：

- `图谱/总览.md`：目标、当前架构位置、分层视图入口、各系统缺口摘要、任务状态、阻塞、待确认项、候选、冲突、健康 warning 和下一步；
- `图谱/索引.md`：按四类正式节点列出完整导航，并分开列出项目/决策支撑记录、状态、来源计数和诊断提示；
- `图谱/视图/架构地图.md`：只绘制系统的 `包含` 层级、系统提供的能力和缺口数量摘要；不放任务节点或任务关系；
- `图谱/视图/开发任务.md`：从 `任务-开发总任务` 展开任务树，按树层级列出任务、状态、依赖、涉及系统、解决缺口、实现项目支撑记录和下一步；`依赖` 以单独的依赖栏展示，不改变缩进；
- `图谱/视图/开发路线.md`：按系统/缺口列出解决任务，作为架构与任务之间的桥接索引；不复制任务树，不生成第二个任务根；
- `图谱/视图/系统联调.md`：只绘制系统之间的 `需要联调` 关系，并列出通过 `涉及系统` 定位到相关系统的任务。

这些文件都是生成页面，人工不在其中维护事实。`图谱/日志.md` 只追加操作审计，不覆盖历史。视图中的 Mermaid 图是阅读投影，节点页面和语义关系才是事实来源。

### 8. 链接健康检查

通过 Obsidian CLI 对当前 workspace 的正式 `图谱/节点/` 页面执行只读检查；支撑记录、候选、原始资料、工作区元数据、总览、索引、视图和日志不作为正式图谱关系源。

检查至少覆盖：

- 未解析链接；
- 孤立节点；
- 无出链节点；
- 缺口没有系统或目标能力；
- 任务没有缺口链路也没有涉及系统；
- 系统层级循环、多个父级或无归属；
- 任务树根是否恰好一个、非根任务是否恰好一个 `分解为` 父级；
- `分解为` 是否存在循环、非任务端点或不可达任务；
- `依赖` 是否被错误地当成任务父子关系；
- 必要的 links/backlinks 查询。

健康问题不自动创建占位节点、不自动修复人工页面、不自动生成正式任务。结果展示在 `图谱/总览.md`；只有问题首次出现、状态变化或解决时才追加 `图谱/日志.md`。健康问题通过稳定指纹追踪，不因重复检查产生噪声。

健康问题是 warning，不阻断成功编译。Obsidian CLI 不可用、目标 workspace 无法访问或写入失败等执行错误才算 compile 失败；失败不自动 commit，保留现场并报告原因。

### 9. 提交

- 有原始资料、节点、支撑记录、生成页面或健康问题状态变化时，创建本地 Git commit；
- 只有 warning 但内容已成功写入时，仍创建 commit；
- 没有任何文件变化时只返回 no-op，不创建空 commit；
- compile 不推送 Git 远端，远端同步由 `push` 负责。

## 输出

完成后报告：

- 当前 workspace；
- 新增/更新的原始资料、正式节点、支撑记录、关系、分层视图、候选和冲突；
- 当前架构位置、任务树面包屑、根任务路径及未定位/未归位任务 warning；
- 重复节点候选及其比较理由；
- 用户需要确认的候选或任务状态变化；
- 总览、索引和分层视图路径；
- 健康检查 warning；
- 是否创建本地 commit 及 commit ID；
- 下一步建议（确认候选、修复链接、继续开发或执行 push）。
