# compile

## 命令

```text
/workspace-sync compile
```

这是 AI 对话中的 workspace-sync 指令。它使用已经选择的当前 workspace，不另加 workspace 参数，也不读取其他迭代。

## 目标

把当前 workspace 的自由格式原始资料，或当前会话中已经明确确认的规划结论，增量整理为 Karpathy LLM Wiki 风格的开发图谱：保留原始资料，维护正式节点、候选、关系、分层视图、冲突和操作日志。

## 输入边界

- 默认扫描当前 workspace 的 `原始资料/*.md`。
- 原始资料不要求固定格式、章节、YAML 或 frontmatter。
- 新规划内容必须追加为新的原始资料，不覆盖以前的原始资料。
- 完整对话不是 compile 的必需输入，也不默认保存完整对话。
- 没有原始资料时，只有当前会话中用户已经明确确认的开发任务/规划结论才能生成新的原始资料；未确认想法只能生成待确认项。

## 步骤

### 1. 确认上下文

读取：

- 根 `SCHEMA.md`；
- 当前 workspace 的 `工作区.md`；
- 当前 workspace 的 `图谱/总览.md`、`图谱/索引.md`、`图谱/日志.md` 和 `图谱/视图/`；
- 受影响的原始资料、正式节点和候选页面。

对 Vault 内容的读取使用 Obsidian CLI。若当前 workspace 不存在，要求用户输入名称并先初始化，不猜测或借用其他 workspace。

### 2. 产生原始资料（仅在需要时）

如果输入来自当前 AI 会话而不是已有原始资料：

1. 从会话中提取用户明确确认的目标、任务、约束、决策和验收边界；
2. 以自由格式 Markdown 创建一个新的 `原始资料/<timestamp>-planning.md`；
3. 记录来源是当前会话和确认范围，不保存完整对话；
4. 没有明确确认内容时，不生成正式原始资料事实，向用户报告待确认项。

原始资料通过 Obsidian CLI 创建，创建后不可被 compile 覆盖。

### 3. 增量编译图谱

对新增或变化的原始资料：

- 识别项目、系统、能力、能力缺口、任务和技术决策；系统之间的联调使用“需要联调”关系，不创建联调点节点；
- 新节点的 `type` 使用中文值：`项目`、`系统`、`能力`、`能力缺口`、`任务`、`决策`；旧节点的英文类型只作为迁移兼容输入；
- 节点文件名使用 `类型-名字.md`，默认生成中文文件夹 `图谱/节点/<类型>/`；改名保留稳定 `id`，同名节点不自动合并；
- 用稳定节点 ID 匹配已有节点；名称相同不能自动合并；
- 在节点正文中维护“关系类型 + 中文节点名 Wiki 链接”的语义 Wiki 链接，例如 `[[能力缺口-订单导入缺少幂等校验]]`；稳定 ID 可作为 alias 保留；
- YAML 只保存身份、类型、状态、时间和来源，不复制关系字段；
- 只允许明确的架构层级关系 `包含`（系统→系统）；任务层级继续使用 `分解为`，任务依赖继续使用 `依赖`，联调任务用 `关联系统` 标明涉及系统，三者不能互换；
- 编译前按“中文类型 + 规范化标题”检查重复；完全重复或高度疑似同义时生成 `kind: duplicate` 的待确认候选，不能自动删除、合并或用新节点覆盖旧节点；
- 同一目标/验收边界的变化保留原任务 ID 并追加修订历史；整体改写时保留旧任务，创建新任务并建立取代关系；
- 任务状态只有用户明确确认或明确事实支持时才变更；不能由 AI 猜测、子任务完成或代码提交静默更新。

### 4. 处理不确定、冲突和候选

- “可能、考虑、待确认、以后再看”等内容进入当前 workspace 的待确认项，不进入确定事实；
- 互相冲突的原始资料都保留，相关节点标记冲突；无冲突内容照常编译；
- 从能力缺口或系统联调需要推导出的工作只生成 `图谱/候选/` 候选页，不直接创建正式任务；
- 用户确认候选后，创建新稳定 ID 的正式任务并保留候选页的转化历史；
- 用户拒绝候选后保留拒绝理由，隐藏在待处理列表中，除非新证据出现，不重复建议；
- 删除任务使用软删除，保留 ID、历史和删除记录。

### 5. 生成分层视图

通过 Obsidian CLI 重建当前 workspace：

- `图谱/总览.md`：目标、分层视图入口、能力缺口、任务状态、阻塞、待确认项、候选、冲突、健康 warning 和下一步；
- `图谱/索引.md`：按节点类型列出完整导航、摘要、状态、来源计数和诊断提示；
- `图谱/视图/系统架构.md`：只绘制系统的 `包含` 层级、系统提供的能力和项目实现映射；
- `图谱/视图/能力缺口.md`：绘制系统 → 能力缺口 → 任务的解决链路；
- `图谱/视图/开发任务.md`：只绘制任务的 `分解为` 层级、状态和 `依赖` 关系；依赖使用虚线或单独列表；
- `图谱/视图/系统联调.md`：只绘制系统之间的 `需要联调` 关系，并列出关联任务。

这些文件都是生成页面，人工不在其中维护事实。`图谱/日志.md` 只追加操作审计，不覆盖历史。视图中的 Mermaid 图是阅读投影，节点页面和语义关系才是事实来源。

### 6. 链接健康检查

通过 Obsidian CLI 对当前 workspace 的正式 `图谱/节点/` 页面执行只读检查；待确认候选、原始资料、工作区元数据、总览、索引、视图和日志不作为正式图谱关系源。

检查至少覆盖：

- 未解析链接；
- 孤立节点；
- 无出链节点；
- 必要的 links/backlinks 查询。

健康问题不自动创建占位节点、不自动修复人工页面、不自动生成正式任务。结果展示在 `图谱/总览.md`；只有问题首次出现、状态变化或解决时才追加 `图谱/日志.md`。健康问题通过稳定指纹追踪，不因重复检查产生噪声。

健康问题是 warning，不阻断成功编译。Obsidian CLI 不可用、目标 workspace 无法访问或写入失败等执行错误才算 compile 失败；失败不自动 commit，保留现场并报告原因。

### 7. 提交

- 有原始资料、节点、生成页面或健康问题状态变化时，创建本地 Git commit；
- 只有 warning 但内容已成功写入时，仍创建 commit；
- 没有任何文件变化时只返回 no-op，不创建空 commit；
- compile 不推送 Git 远端，远端同步由 `push` 负责。

## 输出

完成后报告：

- 当前 workspace；
- 新增/更新的原始资料、节点、关系、分层视图、候选和冲突；
- 重复节点候选及其比较理由；
- 用户需要确认的候选或任务状态变化；
- 总览、索引和分层视图路径；
- 健康检查 warning；
- 是否创建本地 commit 及 commit ID；
- 下一步建议（确认候选、修复链接、继续开发或执行 push）。
