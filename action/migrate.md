# migrate

## 命令

```text
/workspace-sync migrate
```

## 目标

将当前 workspace 的旧版英文目录、旧类型、文件名和语义链接迁移为中文布局及四类正式节点，同时保留稳定 ID、来源、历史和人工正文。迁移只作用于当前 workspace，不跨 workspace 扫描，也不推送远端。

## 需要用户确认

迁移会移动和改名 Vault 页面，属于一次性结构变更。开始前必须展示：

- 当前 workspace；
- 将被迁移的旧目录和页面数量；
- 发现的同名页面；
- 无法自动转换的旧类型、联调点页面或链接；
- 迁移后的目标目录；
- 项目/决策从正式节点降级为支撑记录的清单。

用户明确确认后才执行。确认前只能读取和生成迁移预览，不能写入。

## 链接与类型迁移

1. 先读取全部正式节点的 `id`、旧 `type`、`title` 和路径，建立稳定 ID 到新页面路径的映射。
2. 将旧英文或旧中文类型转换为四类中文类型；`system`/`系统`、`capability`/`能力`、`gap`/`capability_gap`/`能力缺口`、`task`/`任务` 可以直接转换，项目和决策按上表降级为支撑记录。
3. 将旧项目页面移动到 `图谱/说明/项目/`，保留项目 ID、remote、分支、HEAD、dirty、来源和正文；不得继续把它当正式节点统计。
4. 将旧决策页面移动到 `图谱/说明/决策/`，保留 ID、来源、理由和正文；不得继续把它当正式节点统计。
5. 将旧关系 `缺少` 转为 `存在缺口`，将旧任务关系 `关联系统` 转为 `涉及系统`；旧的 `关联项目` 改为支撑记录引用或实现项目元数据，不进入正式关系图。
6. 将正文中指向稳定 ID 的链接改为中文页面名链接，例如 `[[gap-data-import]]` 改为 `[[缺口-数据导入缺少幂等校验]]`；稳定 ID 保留为 alias。
7. 将旧的联调点引用保留为待处理说明，并在迁移报告中列出；不得自动把联调点页面伪装成正式系统、能力、缺口或任务。
8. 对未知类型或无法确认的旧目录创建 `图谱/候选/` 下的待确认迁移候选，记录原始 `type`、路径、ID、aliases、来源、正文、历史和无法判断的原因；候选不进入正式索引或主视图。
9. 对同类型同名节点保留全部页面，文件名追加稳定 ID 短后缀，并生成重复候选；不得静默合并。
10. 重建总览、索引、四个分层视图，再对 `图谱/节点/` 执行链接健康检查；任务没有缺口链路和涉及系统时报告未定位 warning。

所有 Vault 页面移动、创建和修改通过 Obsidian CLI 完成。若本机 CLI 不支持安全移动或改名，停止迁移并报告，不切换到第二套文件接口。

## 结果与回滚

迁移成功后：

- 创建本地 Git commit，不自动 push；
- 报告迁移前后路径、节点类型转换、支撑记录降级、链接转换、重复项和待确认项；
- 保留旧 ID、来源和人工正文；
- 建议用户通过 Git diff 检查后再执行 `push`。

迁移过程中发生 CLI、写入或路径冲突时停止，不创建 commit，并保留已产生的现场。不要使用 force reset 或删除旧目录来“清理”失败现场。
