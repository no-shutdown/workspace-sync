# migrate

## 命令

```text
/workspace-sync migrate [工作区名称]
```

## 目标

将当前会话 workspace 的旧版英文目录、旧类型、文件名和语义链接迁移为中文布局及四类正式节点，同时保留稳定 ID、来源、历史和人工正文。命令默认读取当前会话缓存，也接受显式 workspace 名称作为单次覆盖。迁移只作用于一个已校验的 workspace，不跨 workspace 扫描，也不推送远端。

## 会话边界

- 默认读取 `<run_dir>/.workspace-sync-cache/sessions/<session-id>.json` 中的当前会话 workspace。
- 命令带 `[工作区名称]` 时，先按该名称解析目标 workspace，再回到 `工作区.md` 用稳定 `workspace_id` 校验，并把它作为本次 migrate 的单次覆盖。
- 两者都没有时，停止并要求用户先执行 `list`/`pull` 选择 workspace，或在本次命令中显式提供名称。
- 会话缓存缺失、损坏、`session_id` 非法、workspace 已不存在、`工作区.md` 稳定 ID 不匹配，或运行环境缺少 `session_id` / `run_dir` 且又没有显式参数时，都必须安全停止；不读取用户级 `current_workspace_*`，不按最近更新时间、目录名或其他会话猜测。
- 显式 workspace 在缺少稳定会话 ID 时只作为一次性操作生效；不能写用户级替代缓存，也不能创建全局 current pointer。

## 需要用户确认

迁移会移动和改名 Vault 页面，属于一次性结构变更。开始前必须展示：

- 当前 workspace；
- 将被迁移的旧目录和页面数量；
- 发现的同名页面；
- 无法自动转换的旧类型、联调点页面或链接；
- 迁移后的目标目录；
- 项目/决策从正式节点降级为支撑记录的清单。

用户明确确认后才执行。迁移预览、待确认项和最终写入都必须绑定上面解析出的同一个 workspace。确认前只能读取和生成迁移预览，不能写入。

## 旧版到新版映射

| --- | --- |
| `workspace.md` | `工作区.md` |
| `raw/` | `原始资料/` |
| `wiki/` | `图谱/` |
| `wiki/overview.md` | `图谱/总览.md` |
| `wiki/index.md` | `图谱/索引.md` |
| `wiki/log.md` | `图谱/日志.md` |
| `wiki/nodes/` | `图谱/节点/` |
| `图谱/节点/项目/`、`projects/` / `project` | `图谱/说明/项目/` 支撑记录 |
| `图谱/节点/系统/`、`systems/` / `system` | `图谱/节点/系统/` / `系统` |
| `图谱/节点/能力/`、`capabilities/` / `capability` | `图谱/节点/能力/` / `能力` |
| `图谱/节点/能力缺口/`、`gaps/` / `gap` / `capability_gap` | `图谱/节点/缺口/` / `缺口` |
| `图谱/节点/任务/`、`tasks/` / `task` | `图谱/节点/任务/` / `任务` |
| `图谱/节点/决策/`、`decisions/` / `decision` | `图谱/说明/决策/` 支撑记录 |

| `图谱/视图/系统架构.md`、`wiki/系统架构.md` / `wiki/系统架构` | `图谱/视图/架构地图.md` |
| `图谱/视图/能力缺口.md`、`wiki/能力缺口.md` / `wiki/能力缺口` | `图谱/视图/开发路线.md` |
| `图谱/视图/任务清单.md`、`图谱/视图/开发任务.md`、`wiki/任务清单.md` / `wiki/开发任务` | `图谱/视图/开发任务.md` |
| `图谱/视图/系统联调.md` / `wiki/系统联调` | `图谱/视图/系统联调.md` |

正式节点文件名迁移为 `类型-中文名称.md`。稳定 `id` 不变；旧 ID、旧英文类型和旧文件名写入 `aliases` 或迁移报告，以便历史链接继续解析。

任务层级迁移规则：

- 任务仍只有正式类型 `任务`；若已有页面明确表达总开发目标，将其迁移为 `图谱/节点/任务/任务-开发总任务.md`，保留原 `id`、aliases、正文、状态和历史，并增加 `task_role: 根任务`；
- 只有用户明确确认的总任务才能成为根任务。不能因为任务标题、文件排序、创建时间或项目名称自动挑选根任务；
- 正文已有的 `分解为` 关系迁移为任务树父子关系，已有的 `依赖` 继续作为独立前置关系；不能把依赖、列表顺序或“属于项目”推断成父子关系；
- 迁移后检查根任务恰好一个、每个非根任务恰好一个父级、无环且全部从根可达。缺失父级、多父级、循环或不可达任务保留原页面并报告 warning/候选，不自动改写关系；
- 旧的任务视图只迁移成生成入口 `开发任务.md`；不把视图内容反写成正式任务事实，也不保留第二套任务树。

## 链接与类型迁移

1. 先读取全部正式节点的 `id`、旧 `type`、`title` 和路径，建立稳定 ID 到新页面路径的映射。
2. 将旧英文或旧中文类型转换为四类中文类型；`system`/`系统`、`capability`/`能力`、`gap`/`capability_gap`/`能力缺口`、`task`/`任务` 可以直接转换，项目和决策按上表降级为支撑记录。
3. 将旧项目页面移动到 `图谱/说明/项目/`，保留项目 ID、remote、分支、HEAD、dirty、来源和正文；不得继续把它当正式节点统计。
4. 将旧决策页面移动到 `图谱/说明/决策/`，保留 ID、来源、理由和正文；不得继续把它当正式节点统计。
5. 将旧关系 `缺少` 转为 `存在缺口`，将旧任务关系 `关联系统` 转为 `涉及系统`；旧的 `关联项目` 改为支撑记录引用或实现项目元数据，不进入正式关系图。
6. 将正文中指向稳定 ID 的链接改为中文页面名链接，例如 `[[gap-data-import]]` 改为 `[[缺口-数据导入缺少幂等校验]]`；稳定 ID 保留为 alias。
7. 将旧的联调点引用保留为待处理说明，并在迁移报告中列出；不得自动把联调点页面伪装成正式系统、能力、缺口或任务。
8. 对未知类型或无法确认的旧目录创建 `图谱/候选/` 下的待确认迁移候选，记录原始 `type`、路径、ID、aliases、来源、正文、历史和无法判断的原因；候选不进入正式索引或主视图。
9. 对同类型同名节点保留全部页面，文件名追加稳定 ID 短后缀，并生成重复候选；不得静默合并。
10. 重建总览、索引、架构地图、开发任务、开发路线和系统联调四个分层视图，再对 `图谱/节点/` 执行链接健康检查；任务没有缺口链路和涉及系统时报告未定位 warning，任务树不合法时报告未归位 warning。

所有 Vault 页面移动、创建和修改通过 Obsidian CLI 完成。若本机 CLI 不支持安全移动或改名，停止迁移并报告，不切换到第二套文件接口。

## 结果与回滚

迁移成功后：

- 创建本地 Git commit，不自动 push；
- 报告迁移前后路径、节点类型转换、支撑记录降级、链接转换、重复项和待确认项；
- 报告根任务路径、任务树验证结果、未归位任务以及 `分解为`/`依赖` 的保留情况；
- 保留旧 ID、来源和人工正文；
- 建议用户通过 Git diff 检查后再执行 `push`。

显式 workspace 覆盖成功后，可以更新当前会话缓存；不能写入用户级 `current_workspace_*` 或其他共享默认值。

迁移过程中发生 CLI、写入或路径冲突时停止，不创建 commit，并保留已产生的现场。不要使用 force reset 或删除旧目录来“清理”失败现场。
