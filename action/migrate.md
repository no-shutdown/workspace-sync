# migrate

## 命令

```text
/workspace-sync migrate
```

## 目标

将当前 workspace 的旧版英文目录、节点类型、文件名和语义链接迁移为中文布局，同时保留稳定 ID、来源、历史和人工正文。迁移只作用于当前 workspace，不跨 workspace 扫描，也不推送远端。

## 需要用户确认

迁移会移动和改名 Vault 页面，属于一次性结构变更。开始前必须展示：

- 当前 workspace；
- 将被迁移的旧目录和页面数量；
- 发现的同名节点；
- 无法自动转换的联调点页面或链接；
- 迁移后的目标目录；

用户明确确认后才执行。确认前只能读取和生成迁移预览，不能写入。

## 旧版到新版映射

| 旧路径/类型 | 新路径/类型 |
| --- | --- |
| `workspace.md` | `工作区.md` |
| `raw/` | `原始资料/` |
| `wiki/` | `图谱/` |
| `wiki/overview.md` | `图谱/总览.md` |
| `wiki/index.md` | `图谱/索引.md` |
| `wiki/log.md` | `图谱/日志.md` |
| `wiki/nodes/` | `图谱/节点/` |
| `projects/` / `project` | `项目/` / `项目` |
| `systems/` / `system` | `系统/` / `系统` |
| `capabilities/` / `capability` | `能力/` / `能力` |
| `gaps/` / `gap` | `能力缺口/` / `能力缺口` |
| `tasks/` / `task` | `任务/` / `任务` |
| `decisions/` / `decision` | `决策/` / `决策` |
| `wiki/candidates/` | `图谱/候选/` |
| `integrations/` / `integration` | `图谱/说明/联调/`，不再作为正式节点 |

节点文件名迁移为 `类型-中文名字.md`。稳定 `id` 不变；旧 ID 和旧文件名写入 `aliases`，以便历史链接继续解析。

## 链接与类型迁移

1. 先读取全部正式节点的 `id`、`type`、`title` 和路径，建立稳定 ID 到中文页面的映射。
2. 将旧英文 `type` 转换为中文类型；未知类型不猜测，进入待确认列表。
3. 将正文中指向稳定 ID 的链接改为中文节点名链接，例如 `[[gap-order-import]]` 改为 `[[能力缺口-订单导入缺少幂等校验]]`。
4. 将旧的联调点引用保留为待处理链接，并在迁移报告中列出；不得自动把联调点页面伪装成正式系统或能力节点。
5. 对同类型同名节点保留全部页面，文件名追加稳定 ID 短后缀，并生成重复候选；不得静默合并。
6. 重建总览、索引和四个分层视图，再对 `图谱/节点/` 执行链接健康检查。

所有 Vault 页面移动、创建和修改通过 Obsidian CLI 完成。若本机 CLI 不支持安全移动或改名，停止迁移并报告，不切换到第二套文件接口。

## 结果与回滚

迁移成功后：

- 创建本地 Git commit，不自动 push；
- 报告迁移前后路径、节点类型转换、链接转换、重复项和待确认项；
- 保留旧 ID、来源和人工正文；
- 建议用户通过 Git diff 检查后再执行 `push`。

迁移过程中发生 CLI、写入或路径冲突时停止，不创建 commit，并保留已产生的现场。不要使用 force reset 或删除旧目录来“清理”失败现场。
